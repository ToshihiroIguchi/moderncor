# CLAUDE.md — AI Development Guide for moderncor

## Project Overview

**moderncor** is an R package that provides a unified interface for computing
a wide variety of correlation and association measures through a single function.

- **Repository**: https://github.com/ToshihiroIguchi/moderncor
- **License**: GPL-3
- **Target**: CRAN submission
- **Language**: All code, comments, and documentation in English.
  Communication with users/maintainers in Japanese.

## Architecture

### Core Design Principles

1. **Single entry point**: `moderncor(x, y, method, ...)` for continuous variables
2. **Separate function for categorical**: `moderncor_cat()` (Phase 2)
3. **Consistent S3 output**: All methods return a `moderncor` class object
4. **Graceful dependency handling**: Heavy/specialized packages in `Suggests`,
   with clear error messages when not installed
5. **Prefer original packages**: Always delegate statistical computation to the
   original R package that implements each method. Self-implementation is
   permitted **only** when no existing CRAN/Bioconductor package provides the
   needed statistic (e.g., a p-value that the original package does not compute).
   Even in that case, document the reason for the self-implementation in a code
   comment.

### Dependency Strategy

- **Imports** (always available): `stats`, `energy`, `XICOR`
- **Suggests** (checked at runtime): `minerva`, `Hmisc`, `dHSIC`, `infotheo`,
  `WRS2`, `WGCNA`, `psych`, `ppcor`, `Ball`, `TauStar`, `DescTools`,
  `testthat`, `knitr`, `rmarkdown`

When a Suggests package is needed but not installed, use:
```r
check_suggested <- function(pkg, method) {
  if (!requireNamespace(pkg, quietly = TRUE)) {
    stop(sprintf(
      'Package "%s" is required for method = "%s". Install it with: install.packages("%s")',
      pkg, method, pkg
    ), call. = FALSE)
  }
}
```

## Coding Conventions

### R Code Style

- Use `roxygen2` for all documentation with Markdown support enabled
- Use `snake_case` for function and variable names
- Use `match.arg()` for method selection (consistent with base R `cor()`)
- Prefix internal (non-exported) functions with `compute_` or similar
- Use `stats::cor()` (fully qualified) for external package calls in code
- Use `@importFrom` only for frequently used functions
- All exported functions must have `@export` tag
- All parameters must have `@param` documentation
- All functions must have `@return` documentation
- Include runnable `@examples` (use `\donttest{}` for slow examples)

### S3 Class: `moderncor`

Every method returns a list with this structure:
```r
list(
  estimate     = numeric,        # Correlation estimate
  method       = character,      # Method short name (e.g., "dcor")
  method_label = character,      # Human-readable name (e.g., "Distance Correlation")
  statistic    = numeric | NULL, # Test statistic if available
  p.value      = numeric | NULL, # P-value if available
  n            = integer,        # Sample size
  call         = language        # Original function call
)
```

### Testing

- Use `testthat` edition 3
- Test files: `tests/testthat/test-*.R`
- Test known correlations (perfect positive, perfect negative, zero)
- Test against original package outputs for consistency
- Use `skip_if_not_installed()` for Suggests-dependent tests
- Use `skip_on_cran()` for slow tests

## Key Design Decisions

| Decision | Rationale |
|---|---|
| GPL-3 license | Required by GPL dependencies (energy, Hmisc) |
| `match.arg()` over `rlang::arg_match()` | Consistency with base R `cor()`, fewer dependencies |
| Categorical in separate function | Different input types (factor/table vs numeric) |
| Heavy packages in Suggests | Minimize install burden; not all users need all methods |
| S3 class (not R6/S4) | Simplicity, CRAN compatibility, base R consistency |
| Prefer original package computation | Use the original package's implementation whenever it provides the statistic; self-implement only when no package exists |

## Phase Roadmap

- **Phase 1** (complete): Pearson, Spearman, Kendall, dCor, MIC, HSIC, Xi, Hoeffding, Mutual Info
- **Phase 2** (current): Robust (Biweight, Percentage Bend, Winsorized), Ordinal (Polychoric, Tetrachoric), Partial/Semi-partial, Ball, τ*, `moderncor_cat()` (Cramér's V, Phi, Gamma, Somers' D, Contingency, Tschuprow's T)
- **Phase 3**: CRAN submission, pkgdown site, comprehensive vignettes
